# Token 用量验收说明

## 数据与显示口径

应用日常读取本机 `.claude/projects`、`.codex`、`.grok` 和 `.gemini` 会话日志，写入 `~/Library/Application Support/AgentMonitor/token-usage.db`。不要求 CC Switch 已安装、运行或数据库存在。其他设备及云端任务只有日志实际落到这些本机目录时才会被统计。

总览按模型堆叠，单模型筛选作用于柱子、顶部合计和详情。每格为 100,000,000 Token；模型交界仅改变颜色，分格边界始终从整根柱子的零点计算。缓存属于输入的来源先拆出缓存，避免再次累加；各来源独立上报的缓存创建量按相应语义处理。

模型目录在 `AgentMonitor/Core/Usage/TokenModelCatalog.swift` 集中维护。修改族内排序会重新计算该族深浅，时间范围和筛选不会改变配色。仅登记过的别名合并；新型号保留其身份，族内未知强弱使用中间深浅。

统计状态区分正常计入、确定重复和待核对。原始行不删除；确定重复不进入主图，待核对记录另列条数、Token 和原因。明确对应的新旧 Codex 请求 ID 只计一次。缺少直接请求 ID 的旧代理记录只有在规范化计数、模型和五秒内时间均一致，且全库候选严格一对一时才自动判为跨来源重复；一对多或多对一仍列为待核对。

## 自动验收

使用 README 中的 Debug 测试命令；Debug 构建不会安装到 `/Applications`。

- 几何：0、0.3 亿、1 亿、2.4 亿及不同模型跨过一亿边界。
- 聚合：总览等于各模型合计，单模型和待核对明细同步过滤。
- 日志：四种来源、流式终态补全、累计值、重复事件、父任务历史重放、独立子任务、完整行、文件追加／替换／截断以及超过 50 MB 的日志。
- 独立运行：临时日志根目录和全新临时数据库；CC Switch 路径不存在；验证刷新、追加和重启后的手算总量。
- 迁移：升级前备份、重复执行、原始行保留、确定重复和疑似重叠分别处理。

## 真实数据副本核查

先用 SQLite backup API 创建数据库副本（包含 WAL 中已提交的数据），禁止直接复制一个正在写入的数据库文件。随后运行：

```sh
sh scripts/audit-token-usage.sh /absolute/path/to/usage-copy.db /absolute/path/to/report.json
```

脚本拒绝应用的默认数据库路径。它使用副本执行迁移和本机日志重扫，将迁移前、迁移后、重扫后的用量按日期、模型及统计状态写入 JSON。脚本没有调用 CC Switch 校准。源日志只读；日志中正在产生的新事件可能使不同采样时刻的数据变化。

迁移备份与副本置于同一目录。需要恢复时，应先退出使用目标库的 Debug 实例，保留当前库，再从迁移前备份恢复；不要覆盖仍在写入的库。

## 隔离界面验收

通过 `SWIFT_ACTIVE_COMPILATION_CONDITIONS='DEBUG AGENT_MONITOR_QA'` 构建独立的 Debug 实例，并使用不同的 `PRODUCT_BUNDLE_IDENTIFIER`。QA 窗口使用确定性样本，不打开真实 Token 数据库，也不启用电源模式控制器。窗口内可切换浅色／深色和空数据；其主体复用正式菜单视图与图表。

检查全部时间范围、总览／模型切换、图例点击、悬浮详情、窄窗口边缘以及空数据状态。不要通过 Release 构建启动验收，因为仓库现有 Release 脚本会安装到 `/Applications`。

### 真实副本

冻结的旧库有 94,046 条记录。迁移和日志重扫均在 SQLite backup API 生成的副本上执行，完整首扫耗时 273 秒。按日、模型和状态的明细见 [核查 JSON](evidence/token-usage-real-audit.json)。报告的统计截止时间固定在扫描开始时，扫描期间正在写入的新事件可能已落入副本，但不计入该报告。

| 阶段／状态 | 条数 | Token |
|---|---:|---:|
| 旧库主统计 | 94,046 | 11,564,329,470 |
| 迁移后主统计 | 75,809 | 9,378,799,098 |
| 迁移确认的新旧 ID 重复 | 18,237 | 2,185,530,372 |
| 重扫后主统计 | 77,630 | 9,513,649,973 |
| 重扫后确定重复 | 18,237 | 2,185,530,372 |
| 重扫后待核对 | 1,842 | 334,419,003 |

确定修正以同一请求的新旧 ID、会话、时间和用量完全一致为依据，没有使用 CC Switch 总量作为真值。原始重复行保留，仅调整统计归属。

待核对由 1,542 条父任务关联冲突和 300 条代理／会话疑似重叠组成，不进入主图。29 个日志存在 thread ID 不一致诊断；这些不是已经证明重复的调用。

此次扫描仍无法为 8,330 条主统计历史记录重新建立日志来源路径（其中代理来源 3,959、Claude 2,031、Codex 2,338、Grok 2）。这些历史记录和原来源保留，不能据此次扫描宣称它们全部准确或全部错误。另有 300 条同样没有重建路径的代理记录已列为待核对，确定重复的旧行继续保留。
